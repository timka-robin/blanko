# Blanko for macOS

Небольшое приложение, которое возвращает в Finder создание файлов: текстовый
документ, документ Word и таблицу Excel — прямо из контекстного меню.

Идентификаторы бандла: `com.blanko.mac` (приложение) и `com.blanko.mac.finder`
(расширение Finder). В версиях до 1.2.0 использовался `com.timurgizatullin.newfile`,
поэтому при обновлении с них нужна одна ручная переустановка: для macOS
приложение с другим идентификатором — новое, расширение приходится включать
заново и заново выдавать разрешения.

Blanko живёт только в строке меню: в Dock иконки нет — так и задумано. Иконка
приложения нужна установщику и системе, мини-значок в строке меню — для работы.

## Что умеет

- **Локальные папки:** правый клик → три пункта прямо в меню (расширение Finder).
- **Любые папки, включая iCloud:** правый клик по папке или файлу → **Службы** →
  «Создать текстовый документ / документ Word / таблицу Excel».
- **Горячие клавиши** `⌃⌥⌘1` (текст), `⌃⌥⌘2` (Word), `⌃⌥⌘3` (Excel) — создают файл
  в папке, открытой в Finder (если в фокусе рабочий стол — на рабочем столе).
- **Иконка в строке меню:** показывает, в какую папку попадёт файл, умеет
  проверять обновления, включать автозапуск и открывать настройки.
- В меню у каждого пункта — иконка типа файла: система отдаёт настоящие значки
  Word и Excel, если они установлены.
- В окне настроек те же три действия вынесены строками: значок типа файла,
  кнопка создания файла в открытой папке Finder и подсказка горячей клавиши.
- Файлы `.docx` и `.xlsx` — настоящие форматы Office (Open XML), Word и Excel их открывают.
- Имена не конфликтуют: `Новый текстовый документ.txt`, `… 2.txt`, `… 3.txt`.
- Созданный файл сразу выделяется в Finder, чтобы его можно было переименовать.
- Поддержка **Apple silicon и Intel** (universal binary, macOS 13+).
- **Автообновление** из релизной ветки (см. «Обновления»).

## Установка

Скачать `Blanko-<версия>.dmg` из последнего релиза, открыть образ и запустить
**«Установить Blanko»** — установщик скопирует приложение в `/Applications`,
снимет карантин, зарегистрирует и включит расширение Finder, а затем запустит
Blanko. Если macOS откажется запускать скачанный установщик («неизвестный
разработчик»), щёлкни по нему правой кнопкой → «Открыть» → «Открыть»:
приложение подписано ad-hoc, без Developer ID, нотаризации нет.

Любителям классики: в образе рядом лежит сам `Blanko.app` и ссылка на
«Программы» — можно перетащить. Тогда расширение нужно будет включить вручную
(Системные настройки → Основные → Объекты входа → Расширения) и один раз
запустить приложение.

Тот же установщик работает и из архива `Blanko.app.zip` — там рядом лежит
`Установить.command`:

```sh
curl -L -O https://github.com/timka-robin/blanko/releases/latest/download/Blanko.app.zip
unzip -q Blanko.app.zip
./Установить.command
```

Из клонированного репозитория то же делает `./scripts/install.sh`.

Первый запуск требует двух системных разрешений, оба одноразовые:

1. Доступ к папкам «Рабочий стол» / «Документы» — при первом создании файла там.
2. Управление Finder — при первом использовании горячих клавиш или меню из
   строки меню (нужно, чтобы понимать, какая папка открыта).

## Сборка

Нужны только Command Line Tools (`xcode-select --install`), полный Xcode не
требуется:

```sh
./scripts/build.sh          # universal: arm64 + x86_64
ARCHS=arm64 ./scripts/build.sh   # или только один архитектурный срез
```

Сборка идёт в `$TMPDIR/blanko-build` — вне iCloud, иначе синхронизация добавляет
атрибуты Finder, из-за которых `codesign` отказывается подписывать бандл.

## Ветки и разработка

| Ветка | Назначение |
| --- | --- |
| `main` | рабочая ветка, здесь ведётся разработка |
| `release` | релизная ветка: отсюда приложение обновляется (файл `update.json`) |

Обычный цикл: правки в `main` → сборка → проверка → релиз (см. ниже).
Теги вида `v1.2.0` ставятся на релизной ветке.

## Релиз

```sh
./scripts/release.sh 1.2.0 "Что нового" --push
```

Скрипт по шагам:

1. проставляет версию в `Resources/Info-app.plist` и `Info-appex.plist`;
2. собирает universal-приложение и подписывает;
3. пакует `dist/Blanko.app.zip` и считает SHA-256;
4. пишет `update.json` (версия, ссылка на ассет последнего релиза, контрольная сумма);
5. коммитит версию в `main`, переносит изменения в `release`, коммитит манифест;
6. ставит тег `vX.Y.Z`, отправляет ветки и тег в GitHub;
7. создаёт GitHub Release и прикладывает к нему архив приложения.

Без флага `--push` шаги 5–7 выполняются локально (ветки, коммиты, тег), но
ничего не отправляется — удобно проверить сборку.

## Обновления

Приложение проверяет `update.json` из релизной ветки (с резервными адресами) и
сравнивает версию со своей:

- автоматически — раз в сутки после запуска, тихо;
- вручную — иконка в строке меню → «Проверить обновления…».

Если версия новее, приложение спрашивает подтверждение, скачивает архив с
GitHub Release, сверяет SHA-256 с манифестом, распаковывает, проверяет
идентификатор бандла и подменяет `/Applications/Blanko.app` через отдельный
скрипт (он ждёт выхода приложения, кладёт старую версию рядом как `.old` и
перезапускает новую). Проверка обновлений работает только для копии в
`/Applications` — сборки из репозитория не обновляются.

Репозиторий публичный, поэтому манифест и архив скачиваются анонимно, без
токенов. GitHub не отдаёт их из приватного репозитория — в таком случае
автообновление работать не будет.

## Почему на рабочем столе нет пунктов в меню

Если iCloud синхронизирует «Рабочий стол и Документы», рабочий стол становится
облачной папкой, а его контекстное меню — урезанным: расширения Finder для него
не вызываются, а службы Finder не показываются в меню пустого места. Это
ограничение macOS, а не приложения. Что работает: правый клик по иконке на
рабочем столе → «Службы», горячие клавиши и меню в строке меню.

## Удаление

```sh
./scripts/uninstall.sh
```

Перед удалением выключи автозапуск (иконка в строке меню → «Запускать при входе»).
