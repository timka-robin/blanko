# Как это устроено

## Почему два механизма

Finder Sync расширения (`com.apple.FinderSync`) — единственный способ добавить
свои пункты в само контекстное меню Finder. Но:

1. macOS регистрирует только расширения **в песочнице** (`pkd` молча игнорирует
   подписанные ad-hoc бандлы без `com.apple.security.app-sandbox`).
2. Песочница запрещает расширению писать куда-либо за пределы своего контейнера,
   даже в папку, по которой щёлкнул пользователь (проверено: `EPERM` на
   `file-write-create`).
3. Расширения Finder вообще не используются в папках, которыми управляет
   облачный File Provider (iCloud Drive, «Рабочий стол и Документы» при
   включённой синхронизации, Google Drive, Dropbox).

Поэтому приложение состоит из двух частей:

| Часть | Роль |
| --- | --- |
| `Blanko.app` | фоновый агент в строке меню, без песочницы, выполняет запись файлов |
| `BlankoFinder.appex` | расширение Finder: пункты меню в локальных папках |

Расширение получает клик, но записать файл не может, поэтому передаёт запрос
приложению через URL-схему `newfile-create://create?kind=…&dir=…`.

## Службы Finder

Второй путь — `NSServices` в `Info.plist` приложения. Службы работают в любых
папках, включая облачные, потому что их вызывает Finder и передаёт выбранные
объекты через pasteboard. Ограничение: службы видны только когда есть выделение
(в меню пустого места раздела «Службы» нет вовсе — это поведение Finder).

## Горячие клавиши и меню в строке меню

Для пустых папок и рабочего стола используется AppleScript-запрос
`insertion location` — так приложение узнаёт, какая папка открыта в Finder.
Требует одноразового разрешения на управление Finder.

Горячие клавиши зарегистрированы через Carbon `RegisterEventHotKey` — не требуют
разрешений Accessibility.

## Форматы файлов

`.docx` и `.xlsx` собираются вручную: минимальный набор XML-частей
(`[Content_Types].xml`, `_rels/.rels`, `word/document.xml` и т.д.) упаковывается
собственным ZIP-writer'ом (`Sources/Shared/ZipWriter.swift`, метод store + CRC32).
Внешних зависимостей нет.

## Подпись

Приложение подписывается ad-hoc (`codesign --sign -`) с entitlements песочницы
только для расширения. Apple Developer ID не нужен, но и нотаризации нет:
скачанный архив нужно распаковать и запустить `scripts/install.sh` (он снимает
атрибут карантина) либо разрешить запуск в Системных настройках.
